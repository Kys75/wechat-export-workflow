# Mac 微信版本、降级提钥与日常复用

适用于 macOS 微信。本页补全旧工作流中的版本选择步骤，和 [macOS 权限流程](macos-permissions.md) 配合使用；它不适用于 Windows、Linux 或手机微信。

## 历史上为什么使用 4.1.2

旧工作流记录了以下两种不同结果：

- Mac 微信 4.1.10 / 4.1.11 的内存密钥定位存在兼容问题，采用过降至 **4.1.2** 后重新提钥的路线；提钥后保存密钥，后续可升级客户端。
- 在 **4.1.11** 上使用已经保存且仍匹配数据库的密钥，曾成功刷新和导出。因此“新版难以重新提钥”不等于“新版数据库不能使用旧密钥解密”。

这些是原有实现的历史经验，不是当前重实现扫描器的版本认证。当前仓库验证的是合成数据库加解密、候选密钥 HMAC 与导出流程，未重新对真实客户端执行扫描。不继承旧说明中“任何 4.x 都能用”或“所有公开工具都失效”这样的绝对结论。

## 先判断是否真的需要重新提钥

1. 在微信“关于”中查看当前版本；核对配置选中了正确账户的数据库目录。
2. 若已有密钥，先按 README 刷新。有效密钥可直接复用，不为日常解密或 MCP 查询降级。
3. 文件读取被拒时先处理 Full Disk Access；LLDB 导入失败时先处理 Python/LLDB 匹配；附加失败时按权限文档排查。它们与客户端版本问题不同。
4. 若确实缺少密钥、已有密钥不匹配或出现新消息分片，并且当前客户端无法提取有效密钥，再考虑下面的历史兼容路线。合成测试成功不能证明真实账户密钥可用。

## 手动降到 4.1.2 的完整顺序

这部分由使用者选择并手动操作，程序和 Agent 不会自动卸载、替换或降级微信。

1. **先备份。** 保存工作，正常退出微信，保留当前应用程序包及完整微信数据容器的可恢复本地备份；其中包含私人数据，不上传到仓库。只有导出的 Markdown 并不等于数据库备份。新版客户端可能已迁移数据，旧版不保证能打开。
2. **准备可信的 Mac 微信 4.1.2 安装包。** 优先使用官方可核验的历史分发或自行留存且可验证来源的原版包，确认版本、架构和签名。仓库不分发安装包，也没有确认一个持续可用的官方下载直链；不要把官方网站当前下载按钮误当成 4.1.2。若拿不到可信包，就不能假定这条路线可执行，不运行来源不明的修改版。
3. **替换应用，不清理聊天数据。** 在微信已完全退出后，通过 Finder 安装旧版应用并保留可回退的新版程序包。不要使用卸载清理器，不删除数据容器或 `xwechat_files`。启动后再次确认版本确为 4.1.2；若旧版要求清空记录或执行不可逆迁移，停止并使用备份回退，不强行继续。
4. **避免提钥过程中被自动升级。** 如果该版本提供自动更新选项，可在这次操作期间暂停，并记录之后如何恢复；不要盲目写入未经核实的 Sparkle 偏好键，也不要永久屏蔽安全更新。旧路线曾暂停自动更新，这属于临时操作条件。
5. **提钥。** 登录本人账户并打开相关会话，核对新的 WeChat PID。按 [权限流程](macos-permissions.md) 验证 LLDB/Python，并运行 README 的 `extract-keys`；如确需临时调整 SIP，严格按该文档执行和恢复。密钥输出选一个新文件名，不覆盖仍有用的旧密钥；不要把密钥贴进 Agent 对话。
6. **恢复保护，验证提取结果。** 无论提取成功还是失败，都恢复此次临时调整的 SIP 状态。正常退出微信，以普通用户运行 `refresh`，检查解密、会话最后时间及指定时间范围的导出；“生成了密钥文件”本身不等于已经拿到完整的新消息。
7. **升回受支持的新版本并复核。** 使用可信的当前安装包升级，恢复暂停的自动更新选项；同步后正常退出微信，用已保存密钥再次刷新并核对消息时间和数量。升级、重新登录或新建数据库可能改变密钥及结构；如果失败，明确报告并保留上次快照，不能把旧数据当成刷新成功。

日常流程应回到“已有有效密钥 → 普通用户刷新 → 按会话/日期导出”，不需要每次降级、扫描内存或关闭 SIP。分享版在稳定快照上工作，建议先同步再退出微信后刷新；不要机械照搬旧脚本的热复制前提。

## 给配置 Agent 的判断规则

- 先确认操作系统是 macOS，再区分“首次/重新提钥”和“日常复用密钥”。
- 提供版本背景和可选手动步骤，不将降级当作无条件安装前置，也不能遗漏旧 4.1.2 路线。
- 不自动下载未知旧包、删除微信数据、降级、重签、改变系统保护或永久禁用更新。
- 故障报告分别描述文件权限、进程权限、提钥版本兼容性和数据库解密结果；不要用一个原因解释所有失败。
